# Audit and repair, 2026-10-25

The assistant had been running for months with no monitoring. This is what a review of the
live instance found, what was changed, and how each change was checked.

## Method

1. Read a **copy** of the n8n database (never the running instance): which workflows are
   active, their exact definitions, and the execution history.
2. Compared the live definitions with the earlier public export. They had drifted: fixes made
   in the n8n editor had never reached the repository.
3. Took a full backup (workflow exports and database files) before changing anything.
4. Patched the exported JSON with a script that asserts every replacement matched.
5. Tested the changed Code-node logic against a copy of the database (14 checks, now
   `tests/code_nodes.test.js`).
6. Imported into the live instance, re-activated the workflows, restarted n8n, and ran the two
   failing workflows once.

## Findings and fixes

| # | Finding | Evidence | Fix |
|---|---------|----------|-----|
| 1 | Morning Brief failed every day | Latest run: `toLocaleHour is not a function`. The greeting helper called a method that does not exist | Use `Intl.DateTimeFormat` with the Nairobi time zone |
| 2 | Intel Brief failed every day | Latest run: `A 'json' property isn't an object`. Two nodes returned an array where n8n needs an object | Return `{ items }`; the Hacker News step now accepts the id list in either of the shapes n8n can produce |
| 3 | Intel Brief's "trending" window never moved | The GitHub query had a fixed date of 2026-08-19 | Compute the date as seven days ago |
| 4 | Anyone who found the bot could use it | The Telegram trigger had no restriction and `ParseCommand` did not check the sender; the model also receives the owner's notes | Compare the sender with `TELEGRAM_CHAT_ID` and drop everyone else; deny by default |
| 5 | Reminders did nothing | The handler replied "Reminder set" and stored nothing | Store a task with the due date, and say plainly that timed reminders are not built |
| 6 | "Delete task" could remove many tasks | It deleted every pending task whose title contained the text, with no confirmation | Refuse text under 3 letters; delete only when exactly one task matches, otherwise list the matches |
| 7 | Failures were silent | No workflow had an error handler | New **Error Alert** workflow, set on all five |
| 8 | Evening Reflection failed on network blips | Two inspected failures were DNS errors | Three tries, five seconds apart, on every Telegram, Claude and HTTP node |
| 9 | A crash during a save could corrupt the database | Handlers wrote the file in place | Write to a temporary file, then rename |
| 10 | The public export had drifted from the live system | Node parameters differed in four workflows | This repo is built from the live definitions |

## Result

Run once after the repair: **Morning Brief succeeded and delivered its message; Intel Brief
succeeded, delivered its digest and stored 8 items in a table that had been empty.**

## Not verified

- The sender allow-list, reminder and delete changes are covered by the tests, but have not
  yet handled a real Telegram message.
- Error Alert has not fired in production.
- Evening Reflection's retries have not been exercised by a real network failure.
- Switching the workflows on against a real Telegram bot has not been tried from a fresh
  install. The install scripts themselves were run on a clean n8n: start, database, import, and
  linking credentials to all 17 nodes that need them.
